# 快手短剧知识产权监测 — 项目文档

> 最后更新：2026-05-20

---

## 一、项目总览

### 目标

在 Android 端快手 App 中自动筛查短剧，完成以下流程：

1. 搜索指定短剧名
2. 进入视频播放页 → 截图
3. 找到视频作者 → 进入作者主页
4. 提取作者快手号（ID）
5. 保存截图到 PC
6. 重复至所有短剧处理完毕

### 最终架构

```
PC端 (Python main.py)
  │
  ├─ dump_ui_tree ─────→ 获取UI层级树 → 分析控件坐标
  ├─ deploy_and_run ───→ 发送 action.click(x,y) 到手机执行
  └─ screen_capture ──→ 截图直传 PC，不经过手机存储
       │
       ▼
手机 (AScript App, 无障碍模式)
  执行点击、滑动、输入等操作
```

### 技术选型

| 方案 | 结论 |
|---|---|
| **AScript MCP + UI层级树** | ✅ 选定，100% 准确 |
| OCR 文字识别 | ❌ 复制图标被误识别为数字 0 |
| GELab-Zero 本地视觉模型 | ❌ 硬件可运行但不需要（UI树已够用）|
| CloakBrowser 网页爬取 | ❌ 国内网络无法下载二进制文件 |

### 手机设备

- 型号：HONOR BVL-AN00
- 系统：Android 16
- 连接方式：WiFi 局域网（IP 不固定，脚本可自动扫描发现）
- AScript 运行模式：无障碍模式

## 二、工作步骤（详细）

### 步骤 1：技术方案调研

最初评估了四种方案：

| 方案 | 精度 | 依赖 | 结论 |
|---|---|---|---|
| uiautomator2 | 高 | USB/ADB | 需要数据线，不方便 |
| OCR（PaddleOCR） | 中 | 模型文件+API | 易被图标干扰 |
| 视觉模型（Claude Sonnet/GELab） | 高 | 云端API/本地模型 | 用户无Claude账号，放弃 |
| **AScript MCP + UI层级树** | **100%** | WiFi + AScript App | **选定** |

### 步骤 2：OCR vs UI层级树 精度验证

用实际页面截图 + OCR 识别作者快手号，发现：

```
截图内容:    [快手号：yingbin111] [📋复制图标]
OCR 结果:    yingbin1110   ❌  (复制图标被识别成数字 0)
UI 树读取:   yingbin111   ✅  (读 TextView 原始文本)
```

**结论**：UI 层级树直接读取 Android TextView 控件的 text 字段，是原始数据，100% 精确。OCR 没有 UI 上下文，会把图标误识别为文字。

### 步骤 3：AScript MCP 方案验证

- 安装 AScript MCP（`python -m ascript_mcp.local`）
- 手机安装 AScript App，开启无障碍模式
- WiFi 局域网连接（端口 9096）
- 验证 29 个 MCP 工具可用

**关键发现**：`eval_python` 工具因 ChaQuopy 沙箱限制功能严重受限（连 `1+1` 都返回空），必须用 `deploy_and_run`。

**关键发现 2**：手机上用 `Selector.find_by_id()` 返回的是 Java 数组而非单个 Node，调用 `.click()` 会报错。解决方式：PC 端 `dump_ui_tree` 分析 UI 找坐标，手机只执行 `action.click(x,y)`。

### 步骤 4：脚本迭代

#### v1 — `ascript_kwai.py` / `ascript_short_drama.py`

- 最初尝试在手机端用 AScript Node API 查找控件
- 遇到 `jarray` 问题，`find_by_id().click()` 报错
- 改用 PC 端分析 UI 树 + 坐标点击

#### v2 — `ascript_kwai_scan.py`

- PC 端用 `dump_ui_tree` 获取 UI 树
- 移植 `walk_ui()` 函数遍历查找目标控件
- `deploy_and_run` 发送 `action.click(x,y)` 到手机
- 成功提取第一个作者的快手号

**问题**：导航状态管理不当，第二个短剧提取到和第一个相同的 ID（还在上一个作者的页面）

#### v3 — 导航修复 + 用户预启动快手

- 去掉脚本中的 `am start` 自动启动快手，由用户手动打开
- 剧间导航改用 `am start` 强制跳回主页（比多点几次返回键可靠）
- 搜索按钮自适应多个可能的 ID

#### v4 — `main.py`（当前版本）

- 合并所有历史脚本到单一入口 `main.py`
- 任务菜单设计（`python main.py 0~4`）
- 自动扫描设备 IP（地址变了也不用改配置）
- 批量操作合并（一次 `deploy_and_run` 完成点击→输入→搜索→刷新）

### 步骤 5：截图功能优化

最初截图方案：

```
deploy_and_run 发送 screen.capture() → 保存到手机 /sdcard/ → deploy_and_run 图片回传
```

改为直接方案：

```
screen_capture → base64 → PC 直接保存（screenshots/目录）
```

省去手机存储步骤，效率更高。截图文件名格式：`短剧名_v视频序号_序号.png`

### 步骤 6：批量截图功能

实现 `capture_burst()` 函数，支持：

- 指定截图张数
- 可调节截图间隔（默认 0.5 秒）
- 截图直传 PC 保存

测试结果（2026-05-19，短剧"少爷当腻了只想好好打工"）：

| 视频 | 截图张数 | 状态 |
|---|---|---|
| v1 | 10 | 全部正常（~1MB/张） |
| v2 | 10 | 全部正常（~985KB/张） |
| v3 | 10 | 9张正常，第10张21KB（可能切到过渡页）|
| v4 | 10 | 全部869字节（未正确进入视频页）|

### 步骤 7：性能优化

**问题**：脚本运行缓慢，手机响应间隔长

**分析**：
- 每个 `deploy_and_run` 调用都有部署→执行→等待日志的完整流程
- 搜索过程原来拆了 5 次调用来做（点击搜索→输入→搜索→刷新→检查）
- `log_seconds` 设置过大（8-12 秒）
- Python 端 `time.sleep` 过多（3-5 秒）

**优化措施**：
- 把点击搜索→输入文字→点击搜索→下拉刷新合并为 **1 次** `deploy_and_run`
- `log_seconds` 从 8-12 秒降至 4-8 秒
- `time.sleep` 从 3-5 秒降至 0.5-2 秒
- 截图间隔从 1 秒降至 0.5 秒
- 减少不必要的 `dump_ui_tree` 调用

### 步骤 8：CloakBrowser 网页方案尝试

尝试用 CloakBrowser（反检测 Chromium 浏览器）从 PC 网页端爬取快手数据：

- CloakBrowser 在 C++ 源码层修改 Chromium，57 处指纹补丁
- 能绕过 reCAPTCHA、Cloudflare Turnstile 等反爬检测
- 实际测试：因国内网络限制，~200MB 的二进制文件下载超时失败
- 备用方案 playwright-stealth（JS 注入）也无法通过快手网页的反爬

**结论**：PC 网页方案在国内网络条件下不可行，手机端方案是目前唯一稳定的途径。

## 四、核心功能详解

### UI 树分析

`dump_ui_tree` 返回 Android 界面的完整控件层级，每个节点包含：

```
{
  "text": "控件文本",          # TextView 的原始文本
  "id": "package:id/name",    # 控件 resource-id
  "center_x": 632,            # 控件中心 X 坐标
  "center_y": 1400,           # 控件中心 Y 坐标
  "clickable": true,          # 是否可点击
  "type": "TextView",         # 控件类型
  "childs": [...]             # 子控件列表
}
```

PC 端用 `walk_ui()` 函数按条件（关键词、ID 片段、可点击状态）遍历查找目标控件。

### 快手号提取策略

在作者主页遍历 UI 树，搜索含"快手号"文本的节点，正则提取冒号后的内容。100% 精确，不受界面图标、字体、颜色干扰。

```python
kw_nodes = walk_ui(ui, keyword="快手号")
for n in kw_nodes:
    m = re.search(r'[：:]\s*(\S+)', n['text'])
    if m:
        author_id = m.group(1).strip()
```

### 导航策略

用 `am start` 命令强制跳回快手主页，适用于任何页面状态：

```python
subprocess.run(['am', 'start', '-n',
    'com.kuaishou.nebula/com.yxcorp.gifshow.HomeActivity'])
```

比多点几次返回键更可靠。

## 五、已知问题与局限性

### 当前问题

1. **快手 resource-id 随版本变化** — 搜索按钮的 ID 可能是 `thanos_home_top_search`、`edit_btn` 等，代码中需要适配多个可能值
2. **搜索结果视频覆盖不全** — 第 4 个及以后的视频点击可能无效，原因可能是滚动加载或页面结构变化
3. **键盘搜索按钮坐标不固定** — 输入搜索词后的"搜索"按钮位置随键盘布局变化，当前用固定坐标 `(900, 600)` 点击
4. **导航偶尔不准** — 返回搜索结果页时，如果页面未完全加载，下次点击可能不生效

## 六、踩坑记录

### 1. OCR 把复制图标识别成数字 0

**场景**：从作者主页截图提取快手号时

**错误表现**：
```
截图内容:    [快手号：yingbin111] [📋复制图标]
OCR 结果:    yingbin1110   ❌
UI 树读取:   yingbin111   ✅
```

**原因**：OCR 没有 UI 上下文，把"复制"图标当成了数字 0。

**教训**：Android 原生控件的文本永远用 `dump_ui_tree` 读取，不用 OCR。

### 2. eval_python 返回空结果

**场景**：在手机上执行 Python 代码获取结果

**错误表现**：
```python
await session.call_tool("eval_python", {"code": "1+1"})
# 返回 ()，不是 2
```

**原因**：AScript 运行在 ChaQuopy 沙箱中，`eval_python` 功能受限。

**解决**：用 `deploy_and_run` 替代。

### 3. AScript Node API 返回 Java 数组

**场景**：在手机端代码中用 `Selector` 查找控件

**错误表现**：
```python
el = Selector(0).find_by_id('com.kuaishou.nebula:id/search_btn')
el.click()  # AttributeError: 'jarray...' object has no attribute 'click'
```

**原因**：`find_by_id()` 返回 Java 数组而非单个 Node。

**解决**：PC 端 `dump_ui_tree` 分析 UI，手机端只执行 `action.click(x,y)` 坐标点击。

### 4. Windows 终端中文编码问题

**场景**：Python 脚本在 Windows 终端打印中文日志

**两种方案**：
- UTF-8 模式（`chcp 65001` + `sys.stdout.reconfigure(encoding='utf-8')`）：中文在部分终端乱码
- GBK 模式（默认代码页 936 + `sys.stdout.reconfigure(encoding='gbk')`）：中文在 cmd.exe 正常

当前使用 GBK 模式。

### 5. 多步导航状态管理

**场景**：批量筛查多个短剧，每个短剧需要：主页→搜索→视频页→作者主页→返回

**错误表现**：第一个短剧跑完后返回导航不对，第二个短剧提取到和第一个相同的快手号。

**原因**：从作者主页点一次返回不够，需要：作者主页→返回→视频页→返回→搜索结果→返回→主页。

**解决**：用 `am start` 强制跳回快手主页，一步到位。

### 6. 搜索结果页视频坐标过滤

**场景**：在搜索结果页找视频封面

**错误表现**：状态栏、顶栏的控件也被当成视频封面。

**解决**：y 坐标过滤 `[400, 2500]`，只取屏幕中下部。

### 7. 模型不支持图片输入

当前 deepseek-v4-flash 模型无法查看图片内容。截图只能保存到磁盘供人工审查，不能依赖 AI 自动分析。

### 8. WiFi 设备连接要点

- AScript App 必须开启**无障碍模式**（非快速模式）
- 扫描设备需要 3-5 秒
- 连接成功后保持手机亮屏（AScript 设置"保持唤醒"）
- IP 地址可能随路由器 DHCP 分配变化

### 9. 快手 resource-id 变化

快手不同版本的控件 ID 可能不同。搜索按钮 ID 可能为 `thanos_home_top_search` 或 `edit_btn`。代码需要适配多个备选 ID。

### 核心原则总结

1. **UI 层级树 > OCR** — 永远读 UI 树 text 字段，不用 OCR
2. **PC 分析 + 手机执行** — 分析在 PC 端做（dump_ui_tree），操作在手机端做（action.click 坐标）
3. **deploy_and_run 主力** — eval_python 功能受限，无法使用
4. **状态确认** — 关键步骤后用 dump_ui_tree 确认当前页面
5. **批量操作** — 多个手机操作合并到一次 deploy_and_run，减少延迟
