# AScript MCP + 快手短剧筛查 — 踩坑记录

## 1. OCR 把复制图标识别成数字 0

**场景：** 从作者主页截图提取快手号时

**错误表现：**
```
截图内容:    [快手号：yingbin111] [📋复制图标]
OCR 结果:    yingbin1110   ❌  (复制图标被识别成数字 0)
UI 树读取:   yingbin111   ✅  (读 TextView 原始文本)
```

**原因：** OCR 没有 UI 上下文，把"复制"图标当成了数字 0 字符。只靠截图做文字识别会受界面图标干扰。

**教训：** 凡是 Android 原生控件渲染的文本（TextView），永远用 `dump_ui_tree` 读取 UI 层级树中的 text 字段，不要用 OCR。UI 树读的是控件原始数据，100% 精确，不受图标、字体、颜色干扰。

## 2. eval_python 返回空结果

**场景：** 想在手机上执行 Python 代码获取结果

**错误表现：**
```python
r = await session.call_tool("eval_python", {"code": "1+1"})
# r.content = [TextContent(text='()')]   ← 空元组，不是 2
```

**原因：** AScript 运行在 ChaQuopy（Android 嵌入 Python）沙箱中，`eval_python` 只能执行简单表达式，不支持 `import`、`subprocess` 等操作。返回值序列化也有问题。

**解决：** 用 `deploy_and_run` 替代。这个工具会把代码部署到手机 AScript 项目中完整执行，支持所有 Python 功能，日志和截图都能回传。

```python
r = await session.call_tool("deploy_and_run", {
    "project_name": "zscqAndroid",
    "code": "print('hello')",
    "log_seconds": 10
})
```

## 3. AScript Node API 返回 Java 数组而非单个对象

**场景：** 在手机端代码中用 `Selector` 查找控件

**错误表现：**
```python
from ascript.android.node import Selector
s = Selector(0)
el = s.find_by_id('com.kuaishou.nebula:id/thanos_home_top_search')
el.click()  # AttributeError: 'jarray...' object has no attribute 'click'
```

**原因：** `find_by_id()` 返回的是 Java 数组（`jarray`），即使匹配结果只有一个也是数组。直接调用 `.click()` 会报错。

**解决（两种方案）：**
- **推荐：** 不在手机上做 UI 分析。PC 端用 `dump_ui_tree` 获取 UI 树，分析出目标控件坐标，然后用 `action.click(x, y)` 在手机上执行点击。这样手机只执行坐标点击，不做 UI 查找。
- 如果非要在手机上用 Selector，需要用 `find_all()` + 索引取第一个元素。

```python
# PC 端分析 UI 树
ui = await session.call_tool("dump_ui_tree", {"mode": 0})
# 解析 json，找到目标控件的 center_x, center_y
# 发坐标给手机执行
await session.call_tool("deploy_and_run", {
    "project_name": "zscqAndroid",
    "code": "from ascript.android import action\naction.click(1158, 207)\n",
    "log_seconds": 5
})
```

## 4. Windows GBK 编码导致中文输出报错

**场景：** Python 脚本在 Windows 终端打印中文日志

**错误表现：**
```
UnicodeEncodeError: 'gbk' codec can't encode character '\U0001f4f1'
```

**原因：** Windows 终端默认编码是 GBK，Python 的 `print()` 输出非 GBK 字符时报错。终端也不支持 emoji。

**解决：**
```python
import sys
sys.stdout.reconfigure(encoding='utf-8')  # Python 3.7+
```
同时避免在输出中使用 emoji。

## 5. 多步导航状态管理

**场景：** 批量筛查多个短剧，每个短剧需要：主页→搜索→视频页→作者主页→返回主页

**错误表现：** 第一个短剧跑完后，返回导航没回到正确页面状态。结果第二个短剧提取到的快手号和第一个一样（LW668899000），说明还在上一个作者的页面。

**原因：** 从作者主页只点了一次返回（坐标 `(50, 200)`），但实际可能需要多次返回才能回到快手主页：
- 作者主页 → 点返回 → 视频播放页
- 视频播放页 → 点返回 → 搜索结果页
- 搜索结果页 → 点返回 → 快手主页

每个页面的返回按钮位置也可能不同。

**教训：** 导航状态需要精确管理。两种做法：
- 在每个关键步骤后用 `dump_ui_tree` 确认当前页面（是否回到主页了？搜索按钮可见吗？）
- 或者用 `am start` 重新启动快手，强制回到主页：

```python
subprocess.run(['am', 'start', '-n',
    'com.kuaishou.nebula/com.yxcorp.gifshow.HomeActivity'])
```

## 6. 搜索结果页视频封面需要过滤坐标

**场景：** 在搜索结果页找第一个视频并点击

**错误表现：** 搜到的视频封面控件坐标包含了状态栏、顶栏的控件，点到了错误位置。

**解决：** 对搜索结果设置 y 坐标过滤，只取屏幕中下部的控件：
```python
valid = [c for c in candidates if c['y'] > 400 and c['y'] < 2500]
```
（手机屏幕分辨率 1264×2800，状态栏约 0-200px，顶栏约 200-400px）

搜索结果页容器 `id` 通常包含 `container`、`cover`、`thumb` 等关键词。

## 7. 模型不支持图片输入

**场景：** 想从 PC 端查看手机截图内容

**错误表现：** Read 工具打开截图返回 `[Unsupported Image]`，无法"看到"图片内容。

**原因：** 当前 deepseek-v4-flash 模型不支持多模态输入，不能理解图片内容。

**影响：** 截图只能保存到磁盘供后续人工审查，不能依赖 AI 自动分析截图内容。好在这个项目中作者信息提取全靠 UI 树文本，不依赖截图理解，所以不影响核心功能。

## 8. 同一 WiFi 下的设备连接

**场景：** PC 通过 WiFi 连接手机

**经验：**
- 手机 AScript App 需要开启**无障碍模式**（不要用快速模式）
- IP 地址在 AScript 设置页可见（如 `172.16.1.139:9096`）
- 使用 `connect_device` 工具时指定 `connection_mode: "LocalIP"`
- `scan_devices` 工具扫描需要 3-5 秒，如果搜不到设备先检查手机是否亮屏、AScript 是否在前台
- 连接成功后保持手机亮屏（可设置 AScript 的"保持唤醒"）

## 9. 快手 App 的 resource-id 随版本变化

**经验：** 快手不同版本的控件 ID 可能不同。例如搜索按钮 ID 可能是 `thanos_home_top_search` 或 `edit_btn`。建议在代码中加备选 ID：

```python
search_ids = ['thanos_home_top_search', 'edit_btn', 'search_edit_text']
for id_sub in search_ids:
    candidates = walk_ui(ui, id_sub=id_sub, clickable=True)
    if candidates:
        # ...
```

## 经验总结：核心原则

1. **UI 层级树 > OCR** — Android 原生控件的文本永远从 dump_ui_tree 读取，不用 OCR
2. **PC 分析 + 手机执行** — 分析在 PC 端做（dump_ui_tree），操作在手机端做（action.click 坐标）
3. **deploy_and_run 主力** — 不要用 eval_python，它功能受限。deploy_and_run 才能完整执行代码
4. **状态确认** — 每一步操作后用 dump_ui_tree 确认当前页面状态，不要假设导航成功了
5. **编码先行** — `sys.stdout.reconfigure(encoding='utf-8')` 在脚本入口处加上
