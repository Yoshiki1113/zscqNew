# 单机多手机取证平台设计说明

## 1. 目标

做一个可以由一台电脑统一控制多台手机的取证平台。

平台先支持微信视频号，后续再扩展到其他平台。

目标不是单纯跑脚本，而是形成一套可展示、可复核、可聚合、可扩展的取证工作台。

## 2. 核心能力

- 一键发起取证
- 支持多台手机并行或串行任务
- 自动检查设备连通性
- 自动输出取证日志
- 自动保存截图、录屏、JSON、HTML
- 自动生成证据包链接
- 支持人工复核和状态标注
- 支持按博主聚类统计
- 支持侵权样本池和白名单池

## 3. 技术目标

平台需要解决的不是“能不能点”，而是：

- 多台手机如何稳定接入
- 每台手机如何独立执行任务
- 每条证据如何唯一标识
- 每份证据如何可追溯
- 每个复核状态如何保存
- 每个博主如何聚合统计

## 4. 系统分层

### 4.1 设备层

负责手机连接和会话管理。

包括：

- USB 连接
- ADB 连接
- AScript / MCP 连接
- 录屏能力
- 截图能力

### 4.2 任务层

负责调度取证任务。

包括：

- 任务创建
- 任务排队
- 任务执行
- 任务重试
- 任务终止
- 任务状态流转

### 4.3 证据层

负责保存和组织取证结果。

包括：

- 原始 JSON
- 同名 HTML 预览
- 截图
- 录屏
- 日志
- 证据包目录

### 4.4 分析层

负责按博主、视频、平台聚合统计。

包括：

- 侵权数量
- 白名单数量
- 不确定数量
- 账号聚类
- 平台聚类
- 时间趋势

## 5. 单机多手机架构

### 5.1 推荐方式

推荐一台电脑 + 多台 Android 手机。

每台手机都要有独立的：

- `device_id`
- 任务上下文
- 日志目录
- 截图目录
- 录屏目录
- 证据包目录

### 5.2 连接方式

可用方式：

- `ADB USB`
- `ADB over TCP/IP`
- `AScript/MCP`

推荐优先级：

1. USB ADB
2. 局域网 ADB
3. AScript 作为自动化执行层

### 5.3 设备隔离

每台设备都必须隔离：

- 任务状态
- 录屏文件
- 截图文件
- OCR 中间结果
- 取证日志
- 复核状态

不允许多台手机共用同一个输出目录。

## 6. 任务调度模型

### 6.1 调度方式

平台建议采用“中央调度器 + 设备 worker”的结构。

结构如下：

- 调度器负责分配任务
- 每台手机对应一个 worker
- worker 只处理自己的设备
- 调度器只做协调，不直接操作页面

### 6.2 任务状态

建议状态：

- `pending`
- `preparing`
- `running`
- `reviewing`
- `completed`
- `failed`
- `stopped`

### 6.3 任务流

1. 用户创建任务。
2. 调度器分配设备。
3. worker 做前置检查。
4. 设备准备完成后开始取证。
5. 取证中实时记录日志。
6. 取证结束后生成证据包。
7. 任务进入结果展示。
8. 结果进入复核或聚合分析。

## 7. 设备前置检查

一键取证前必须检查：

- 手机是否通过 USB 连接
- `adb devices` 是否可见
- AScript 是否在线
- 录屏是否可用
- 存储目录是否可写
- 当前设备是否已授权
- 当前任务目录是否存在

前置检查必须可视化，不能只在后台失败。

## 8. 证据包规则

每条视频必须生成一个完整证据包。

建议包含：

- 原始 JSON
- 同名 HTML
- 播放页截图
- 博主资料卡截图
- 博主更多信息页截图
- 引流标记截图
- 引流账号截图
- 录屏文件
- 日志文件

证据包必须能从页面直接点击跳转。

## 9. 视频标识符

`video_identifier` 是单条视频的唯一标识。

要求：

- 不依赖分享链接
- 同一视频多次点击分享仍应保持一致
- 不同视频不能混淆

建议来源：

- 搜索关键词
- 视频标题
- 博主名称
- 视频号 ID
- 引流标记文本
- 播放页截图 hash
- 其他稳定 OCR 字段

## 10. 人工复核

人工复核状态：

- `侵权`
- `白名单`
- `不确定`

规则：

- 默认新结果先进入 `不确定`
- 人工可改为 `侵权`
- 人工可改为 `白名单`
- `不确定` 始终保留在待复核池
- 每次变更都要记录操作者和时间

复核按钮必须在结果页和详情页都能快速触达。

## 11. 博主聚合

按以下维度聚类：

- `video_channel_id`
- 博主名称
- 主体类型
- 企业全称

聚合后展示：

- 总视频数
- 侵权数
- 白名单数
- 不确定数
- 最近取证时间
- 最近更新时间

聚合页里应能直接展开该博主所有证据包。

## 13. 页面设计

### 13.1 首页

首页只做三件事：

- 新建任务
- 查看设备状态
- 查看最近任务

首页第一屏必须放得下“一键取证”按钮。

### 13.2 任务执行页

任务执行页用于看实时过程。

必须展示：

- 当前任务
- 当前设备
- 当前步骤
- 实时日志
- 当前截图
- 当前录屏状态

### 13.3 结果页

结果页按视频展示。

每条卡片至少显示：

- 博主名称
- 视频号 ID
- 主体类型
- 企业全称
- 喜欢数
- 收藏数
- 转发数
- 评论数
- 视频标识符
- 证据包入口

### 13.4 详情页

详情页是单条视频的完整证据入口。

左侧：

- 结构化字段
- 复核状态
- 任务日志摘要

右侧：

- 录屏播放器
- 截图画廊
- JSON
- HTML 预览链接

### 13.5 复核池页

复核池页用于集中处理 `不确定`。

支持：

- 批量复核
- 快速翻页
- 按作者筛选
- 按平台筛选
- 按时间筛选

### 13.6 博主页

博主页用于聚合统计。

展示：

- 博主概览
- 侵权统计
- 视频列表
- 对应证据包
- 时间线

## 14. 交互要求

- 所有耗时操作必须有进度提示。
- 所有失败必须能看到原因。
- 所有证据包必须一键跳转。
- 所有复核状态必须即时保存。
- 所有筛选必须可回退。
- 所有任务必须可重试或停止。

## 15. UI 风格规范

### 15.1 气质

- 专业
- 克制
- 清晰
- 偏取证后台风格

### 15.2 字体

- 中文：`PingFang SC`、`Microsoft YaHei`
- 数字和英文：系统无衬线
- 标题更重，正文更稳
- 字距正常，不做夸张排版

### 15.3 色彩

推荐四色体系：

- 主色：深青绿或蓝绿色
- 强调色：橙红或琥珀色
- 成功色：绿色
- 风险色：红色

状态建议：

- `侵权`：红
- `白名单`：绿
- `不确定`：黄

避免：

- 大面积紫色
- 过重渐变
- 花哨背景
- 低对比浅灰字

### 15.4 卡片

- 圆角 8px 左右
- 边框轻
- 阴影浅
- 信息密度高
- 不要做漂浮感太强的装饰卡

### 15.5 按钮

- 主按钮只放最关键动作
- 次按钮用于辅助操作
- 危险按钮用于停止、删除、标红
- 复核按钮要明显且固定位置

### 15.6 状态标签

- 使用小胶囊
- 颜色区分清楚
- 状态必须可扫读

## 16. 布局规范

### 16.1 总体布局

- 顶部：导航栏
- 中间：主工作区
- 右侧：详情或辅助面板
- 底部：日志或操作区

### 16.2 首页布局

- 上方：任务入口
- 中间：设备检查
- 下方：最近任务

### 16.3 列表页布局

- 左侧：任务列表或结果列表
- 右侧：详情预览
- 支持表格和卡片两种模式

### 16.4 详情页布局

- 上部：字段摘要
- 中部：录屏播放器
- 下部：截图和原始 JSON

### 16.5 博主页布局

- 上部：博主统计概览
- 中部：视频列表
- 右侧：证据包和复核状态

## 17. 多手机并行建议

### 17.1 初始规模

建议先从：

- 1 台电脑
- 2 台手机

开始验证。

### 17.2 目录隔离

按设备隔离：

- `device_id`
- `task_id`
- `json`
- `html`
- `screenshots`
- `media`
- `logs`

### 17.3 并发策略

优先建议：

- 先串行调度
- 再半并行
- 最后全并发

原因：

- 取证稳定性优先
- 多设备并行会放大掉线和资源竞争问题

## 18. 开发顺序

1. 首页 + 设备检查
2. 任务执行页 + 实时日志
3. 结果页 + 证据包链接
4. 复核池
5. 博主聚合页
6. 多设备调度
7. 其他平台接入

## 19. 当前代码对接点

当前微信取证代码已经具备：

- JSON 落盘
- 同名 HTML
- 截图保存
- 录屏保存
- `video_identifier`
- `subject_type`
- `company_full_name`

所以平台前端可以直接消费这些结果文件，不需要重做证据底层。
