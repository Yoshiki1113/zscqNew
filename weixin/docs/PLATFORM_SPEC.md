# 取证平台设计说明

## 1. 目标

做一个可扩展的取证平台，先支持微信视频号，后续可接入其他平台。

平台核心能力：

- 一键取证
- 取证前环境检查
- 取证日志实时输出
- 证据包统一展示
- 人工复核与标注
- 博主聚合分析
- 侵权统计与待复核池

## 2. 设计原则

- 先跑通单平台闭环，再抽象多平台能力。
- JSON 作为机器事实源，HTML 作为人工预览层。
- 每条视频必须能追溯到原始截图、录屏、JSON、日志。
- 人工复核是最终业务事实，不依赖自动判断结果。
- 所有页面都要支持“快速扫一眼”和“点开深入看”两种使用方式。

## 3. 角色

- 取证员：发起任务、查看日志、导出证据包。
- 复核员：对单条视频做侵权/白名单/不确定标注。
- 管理员：管理平台配置、任务模板、用户权限。

## 4. 核心对象

### 4.1 Task

- 平台
- 关键词
- 取证范围
- 任务状态
- 开始时间
- 结束时间
- 实时日志
- 错误信息

### 4.2 EvidenceRecord

- 搜索词
- 视频标识符
- 博主名称
- 视频号 ID
- 主体类型
- 企业全称
- 喜欢数
- 收藏数
- 转发数
- 评论数
- 视频链接
- 录屏路径
- 截图列表
- 原始 JSON 路径
- HTML 预览路径

### 4.3 ReviewResult

- 状态：`侵权` / `白名单` / `不确定`
- 复核人
- 复核时间
- 备注

### 4.4 AuthorCluster

- 博主名称
- 视频号 ID
- 主体类型
- 企业全称
- 总视频数
- 疑似侵权数
- 已确认侵权数
- 白名单数
- 不确定数

## 5. 页面结构

### 5.1 首页

用途：发起一键取证。

组件：

- 平台选择
- 关键词输入
- 任务模板选择
- 取证次数
- 复核策略
- 一键取证按钮
- 环境检查状态灯

必备前置检查：

- 手机 USB 是否连接
- ADB 是否可用
- AScript 是否可连接
- 录屏能力是否可用
- 存储目录是否可写

### 5.2 任务运行页

用途：实时看取证执行过程。

展示内容：

- 当前步骤
- 实时日志
- 当前截图缩略图
- 当前录屏状态
- 失败原因
- 重试按钮

### 5.3 结果列表页

用途：按视频维度查看取证结果。

每个卡片显示：

- 博主名称
- 视频号 ID
- 主体类型
- 企业全称
- 喜欢数、收藏数、转发数、评论数
- 视频链接
- 视频标识符
- 复核状态
- 证据包入口

### 5.4 证据详情页

用途：查看单条视频的完整证据包。

左侧：

- 结构化字段
- 复核状态
- 任务日志摘要

右侧：

- 录屏播放器
- 截图画廊
- 原始 JSON
- HTML 预览链接

### 5.5 复核池页

用途：处理“不确定”样本。

支持：

- 逐条复核
- 批量复核
- 按平台 / 博主 / 时间筛选
- 快速切换上一条 / 下一条

### 5.6 博主聚合页

用途：按博主聚类，查看累计侵权情况。

展示内容：

- 博主名称
- 视频号 ID
- 主体类型
- 企业全称
- 累计视频数
- 累计侵权数
- 累计白名单数
- 累计不确定数
- 侵权视频列表
- 对应证据包入口

## 6. 一键取证流程

1. 用户输入关键词和平台。
2. 点击一键取证。
3. 平台做前置检查。
4. 检查通过后启动取证任务。
5. 实时输出日志。
6. 任务完成后自动生成证据包。
7. 结果进入列表页和作者聚合页。
8. 复核状态可随时更新。

## 7. 证据包规则

每条视频必须生成同名证据包，至少包含：

- `result_*.json`
- `result_*.html`
- 播放页截图
- 博主资料卡截图
- 博主更多信息页截图
- 引流相关截图
- 录屏文件

证据包链接必须可直接点击打开。

## 8. 视频标识符规则

`video_identifier` 代表一个视频的稳定唯一标识。

要求：

- 不能依赖分享链接
- 同一个视频多次点击分享链接，标识符仍应一致
- 同一博主不同视频不能混淆

建议生成来源：

- 搜索词
- 视频标题
- 博主名称
- 视频号 ID
- 引流标记文本
- 播放页截图 hash
- 其他稳定 OCR 证据

## 9. 复核状态机

状态：

- `侵权`
- `白名单`
- `不确定`

流转规则：

- 默认新结果进入 `不确定`
- 复核员可改成 `侵权` 或 `白名单`
- `不确定` 始终保留待复核池
- 所有状态变更要保留操作人和时间

## 10. 博主聚合规则

聚合维度：

- `video_channel_id`
- `博主名称`
- `主体类型`
- `企业全称`

统计指标：

- 总视频数
- 侵权数
- 白名单数
- 不确定数
- 最近取证时间
- 最近更新状态

聚合页要支持一键展开该博主下的所有证据包。

## 11. UI 风格规范

### 11.1 整体气质

- 偏“专业取证后台”
- 克制、清晰、稳重
- 少装饰，多信息密度
- 不做娱乐化、营销化视觉

### 11.2 字体

- 中文：`PingFang SC` / `Microsoft YaHei`
- 英文和数字：系统无衬线即可
- 标题字重更高，正文保持中等字重
- 不要夸张字距，不要大面积全大写

### 11.3 色彩

建议使用 4 色体系：

- 主色：深青绿或蓝绿色
- 强调色：橙红或琥珀色
- 成功色：绿色
- 中性色：灰白、石墨灰

建议状态色：

- `侵权`：红
- `白名单`：绿
- `不确定`：黄

避免：

- 大面积紫色系
- 过重渐变
- 花哨背景
- 低对比浅灰字

### 11.4 视觉层级

- 页面标题最强
- 模块标题次强
- 字段标签弱化
- 值区清晰可扫读

### 11.5 组件风格

- 卡片圆角 8px 左右
- 边框轻，阴影浅
- 按钮分主按钮、次按钮、危险按钮
- 状态标签采用小胶囊
- 复核状态使用明显颜色

## 12. 布局规范

### 12.1 总布局

- 顶部导航固定
- 主内容区左右分栏
- 左侧用于列表和主要操作
- 右侧用于详情、播放器、筛选、复核

### 12.2 首页布局

- 第一屏必须看到“一键取证”
- 上方是任务参数
- 中间是前置检查
- 下方是最近任务

### 12.3 列表页布局

- 以卡片列表或表格为主
- 每行或每卡只显示高频字段
- 详情放到抽屉或详情页
- 支持按博主、状态、平台、时间筛选

### 12.4 详情页布局

- 上部：字段摘要
- 中部：录屏播放器
- 下部：截图和原始 JSON
- 复核按钮放在最容易点到的位置

### 12.5 聚合页布局

- 顶部：博主概览统计
- 中部：视频列表
- 右侧：证据包和复核状态

## 13. 交互规范

- 所有长耗时操作必须有进度状态。
- 所有失败必须可解释、可重试。
- 证据包链接必须一键直达。
- 复核按钮必须显眼，不埋在二级菜单里。
- 切换复核状态后要立即保存。
- 表格/列表支持快捷筛选和搜索。

## 14. 开发顺序建议

1. 任务首页 + 前置检查
2. 取证执行日志页
3. 结果列表页
4. 证据详情页
5. 复核池页
6. 博主聚合页
7. 多平台抽象层

## 15. 当前实现对接点

现有微信取证代码已经具备：

- JSON 落盘
- 同名 HTML 预览
- 录屏文件保存
- 截图保存
- 视频号 ID 提取
- 主体类型与企业全称提取

后续平台页面可以直接消费这些文件，不需要重做证据底层。
